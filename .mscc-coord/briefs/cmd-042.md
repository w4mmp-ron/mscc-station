## Survey (Overseer): nothing else needs changing

- **ms-sdr** (Windows `ms-sdr-MKII`, `linux/` + `rpi/` `ms-sdr-linux`), `source/user_controls.c`: **no clamp or validation.**
  - 0xD1 is forwarded to recv and stored in `uint8_t Filter_High_index` (Win `:1264-1267`, linux `:1309-1312`, rpi `:1307-1310`).
  - The value is saved/loaded as `FILTER_HIGH_INDEX` (`:255-258`).
  - On connect it's re-sent to recv as 0xD1 (Win `:574`, linux `:576`) and to the GUI as 0xDD default (`:651` / `:657`).
  - 5/6 store and replay fine once recv knows them. **No ms-sdr edit.**
- **GUI echo of 0xDD:** a stored 5/6 comes back to the client as the "default hi-cut". WPF guards this in **cmd-041**, because the default listbox only has 5 items. Avalonia already clamps it to 0..4 (`MainViewModel.cs:6520`). Avalonia is out of scope, note only.
- **SDRcore-trans:** no 0xD1 handler (TX hi-cut is 0xD3). No edit.
- **mscc-init** copies have the same switch but it's the standalone init/cal tool. Out of scope. `Solidus/` is not live, so don't edit it.
