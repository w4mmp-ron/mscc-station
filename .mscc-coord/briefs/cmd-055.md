## Locked v1 design

1. **Servers manage LIVE cal only while running**
   - **trans** owns `power_cal.ini` create / load / save (as on Pi / after cmd-048).
   - **ms-sdr** manages IQ / freq live as today (read/report; seed-if-missing / reset as today).
   - **No** live → parked write-through mirrors during normal cal (drop continuous `Factory_mirror_live_to_cal` on every QRP/IQ save).

2. **QRP / IQ popup saves stay → LIVE** (unchanged UX). Operator cal edits write live only until they press Save settings or a radio-line change parks them.

3. **New always-visible left-panel WPF button: "Save settings"** (or "Save configurations")
   - Copies live cal for the **current** radio line into `%LocalAppData%\MSCC-NET9\cal\<line>\` (parked backup).
   - Tip text on cal tabs (roughly): *"For next session / radio swap, press Save settings."*

4. **On MSCC load / radio detect** (detection-driven; **no** primary manual switch-radio tool):
   - Use `LAST_LINE` + detected model (`Factory_line_from_major` lines: proficio-legacy, proficio-mkii, geminus-legacy, geminus-mkii, ultimus-legacy, ultimus-mkii).
   - **Same radio** → leave live alone.
   - **Different radio** → stash live into previous line's parked (`cal\<prev>\`) if needed, then parked → live for the new line.
   - **Brand-new radio** (no parked set) → factory → parked → live.
   - Detection-driven only for v1. Do **not** build a primary manual switch-radio tool.

5. **UI / S/W / mode / etc.** stay save-on-the-fly as today — **out of scope**.

6. **No auto-park on exit** for v1. If the operator never pressed Save settings and does not swap radios, live stays as left.

7. **Host / ship:** windows-new-hp; WPF + ms-sdr as needed; commit locally; do **not** push.

## Implementation notes (Stew's call)

- **Where the swap runs:** keep or reshape ms-sdr `Factory_seed_live_inis` / radio-detect path (already has `LAST_LINE.txt` + `cal\<line>\`), and/or trigger from WPF once the model is known. Goal: detection-driven park/restore; do not steal `power_cal.ini` ownership from trans (ms-sdr may copy the live file for park/restore only).
- **Park set for v1:** at least `iq.ini` + `power_cal.ini` (what the old auto-swap handled). Include `freq_cal.ini` only if Stew wants it in the parked line set.
- **Remove** continuous `Factory_mirror_live_to_cal` on save paths (`power_calibration.c`, `iq.c`, inside `Factory_reseed_live_file`). Parked updates come from: (a) explicit **Save settings**, (b) detection stash on line change.
- **Keep** seed-if-missing for live files that ms-sdr still owns (`iq.ini`, `freq_cal.ini`); **keep** `Factory_reseed_live_file` for IQ Reset / FREQ CAL RESET (factory → live, no required mirror).
- **QRP Reset `0xAA`:** leave ignored (WPF never sends; trans owns the file).
- **Paths:** live under `%LocalAppData%\MSCC-NET9\` (existing `G_l_path`); parked under `...\MSCC-NET9\cal\<line>\`; `LAST_LINE.txt` under `...\MSCC-NET9\cal\`.
- **WPF:** always-visible left-panel button + tip on cal tabs. Wire Save settings to copy current-line live → `cal\<line>\` (and refresh `LAST_LINE` if that is part of the design Stew chooses). Version bump as Stew usually does for WPF.
- **Do not** implement Avalonia, Pi, or Ubuntu in this cmd.

## Test

1. Same radio, restart servers / MSCC: live cal unchanged (no unwanted parked overwrite of live).
2. QRP-calibrate a band; restart **without** Save settings: live value still present (servers manage live only; no exit auto-park).
3. Press **Save settings**; confirm `cal\<current-line>\` has updated `iq.ini` / `power_cal.ini` (and any other files Stew included).
4. Swap to a different detected radio: previous live parked under old line; new line's parked (or factory) loaded to live; operate; swap back: prior cal restored.
5. Brand-new line (delete that line's `cal\<line>\` folder): factory → parked → live; radio usable.
6. IQ Reset / FREQ CAL RESET still reseed from factory to live.
7. Cal-tab tip visible; Save settings always visible on the left panel.
8. UI / mode / S/W still save on the fly (smoke only — no change expected).
