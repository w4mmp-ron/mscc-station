## Implement (Avalonia only)

### A) Remote AF Phones / Digital radios (independent path)

1. Add **`RemoteDigitalAudio`** on `MainViewModel` (bool). This is the **remote** path flag. **Do not** drive remote Path / RemoteWireOpcode from local `IsDigitalAudio`.
2. Add **PathPhones** / **PathDigital** radio buttons to `RemoteAfWindow.axaml` (same idea as WPF `RemoteAfWindow.xaml`), with a `Path_Changed` handler that sets `_vm.RemoteDigitalAudio` from `PathDigital.IsChecked`.
3. `RefreshPath()` must use **`_vm.RemoteDigitalAudio`** (not `IsDigitalAudio`) for title, headings, EQ visibility, VAC hints, device auto-pick, and mic volume source.
4. Sync radio checked state in RefreshPath: `PathPhones.IsChecked = !digi; PathDigital.IsChecked = digi`.
5. When `RemoteDigitalAudio` changes while Remote is on: push remote wire opcode (R-Phones **2** vs R-Digital **3**), restart AF devices as needed, call `RefreshPath`. Mirror WPF `OnRemoteDigitalAudioChanged` policy — **do not** write local Phones/Digital chrome from the remote path.
6. `RemoteWireOpcode()` / remote start path: use `RemoteDigitalAudio`, not `IsDigitalAudio`. Local `LocalAudioOpcode()` stays on `IsDigitalAudio`.

### B) Remote Digital mic slider

1. `ClientSettingsStore`: add `RemoteDigitalMicVolume` (int, default **100**, clamp 0–100). Load/save INI key **`REMOTE_DIGI_MIC_VOL`**. Keep phones on **`REMOTE_MIC_VOL`** / `RemoteMicVolume`.
2. `RefreshPath` when digi: `MicVolumeSlider.IsEnabled = true`; set Value from `RemoteDigitalMicVolume` (not hard-coded 100); apply `RemoteAf.MicVolume = pct / 100f`.
3. When phones: Value from `RemoteMicVolume` (existing).
4. `MicVolume_Changed`: always apply `RemoteAf.MicVolume = v/100f`. If remote digi → persist `RemoteDigitalMicVolume`; if phones → persist `RemoteMicVolume`. **Remove** the digi branch that forces `1.0f` and returns early.
5. Confirm `LinuxMicSender` still multiplies by `Volume` (it does today) — no host change.

### C) Main Phones / Digital not selectable while Remote

1. While `RemoteAudio == true`, main **Phones** and **Digital** buttons must be **not selectable** (`IsEnabled=false` or CanExecute false — Stew: not selectable).
2. Exit Remote **only** via the **Remote** control (toggle Remote off). Do **not** make main Phones/Digital clickable as an exit path.
3. **Documented difference vs WPF:** WPF (cmd-033) dims local Phones/Digital while Remote but they can still be used to leave Remote / select local path. Avalonia for cmd-040 is **stricter** — buttons disabled; leave via Remote only. Keep Remote window Path Phones/Digital fully usable.
4. Do not leave a false “selected” chrome on main Phones/Digital that implies Remote changed the local path. Remote path lives in the Remote window / `RemoteDigitalAudio` only.

### D) 0xBC / TxSetByServer = WPF cmd-033 ownership

In `TxSetByServerReported` handler:

1. Set `TxSetByServer = v` only (keeps `CanUserControlTransmit` / disables user PTT+TUN).
2. **Do NOT** set `TuneMode` from 0xBC.
3. **Do NOT** set `PttOn` from 0xBC (no lit PTT / no `OnPttOnChanged` side effects).
4. Audit: while `TxSetByServer`, never send TUN / TX_ON / tune-power as a reaction to 0xBC. PTT and TUN unavailable while server owns TX. **No lighting TUNE for WSJT digi.**

Log can stay informational, e.g. server owns TX / PTT-TUN locked — without forcing faceplate TX chrome.
