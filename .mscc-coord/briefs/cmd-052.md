## 1. What exists today (Avalonia 0.6.68) — the bug

Call chain (Remote checkbox / ToggleRemoteAudio):

- `ToggleRemoteAudio` (`MainViewModel.cs` ~`:2576-2580`) flips `RemoteAudio`.
- `OnRemoteAudioChanged(true)` (~`:2254-2274`): `PushAudioToRadio("Remote ON")` then **`StartRemoteAf("Remote ON")`**.
- Same `StartRemoteAf` is also used from Connect when sticky `REMOTE_AUDIO=1` (~`:1320-1322`, reason `"connect"`).

`StartRemoteAf` today (~`:2291-2328`):

```csharp
internal void StartRemoteAf(string reason)
{
    if (!IsRemoteAudioAllowed) { ...; return; }
    try { Services.RemotePhonesLauncher.StopAll(); } catch { /* in-UI AF */ }
    RemoteAf ??= new RemoteAfEngine();
    RemoteAf.Log -= OnRemoteAfEngineLog;
    RemoteAf.Log += OnRemoteAfEngineLog;
    RemoteAf.PlayVolume = RemotePlayVolume / 100f;
    RemoteAf.MicVolume = RemoteMicVolumeLinear();
    RemoteAf.PlayMuted = RemotePlayMute;
    ApplyRemoteAfDevices();
    try
    {
        RemoteAf.StartRx();
        string host = (Host ?? "").Trim();
        if (string.IsNullOrEmpty(host))
            host = "127.0.0.1";
        RemoteAf.StartMic(host);
        string seat = RemoteDigitalAudio ? "Digital VAC" : "Phones";
        AppendLog($"Remote AF started ({reason}) {seat} TX host={host}:9101 micVol={RemoteAf.MicVolume:0.00}");
    }
    catch (Exception ex)
    {
        AppendLog($"Remote AF start failed: {ex.Message}");
    }
    if (RemoteDigitalAudio)
        StartRemoteCat();
    else
    {
        StopRemoteCat();
        AppendLog("CAT idle (phones remote — PTT/tune in MSCC)");
    }
    ShowRemoteAfWindow();   // always, even after failed start
}
```

Gaps vs cmd-051's `ApplyRemoteAfDevicesAndRestart` (~`:2401-2435`):

1. **No `RemoteAf.Stop()` before open.** After Remote OFF, `StopRemoteAf` stops streams but **keeps** the `RemoteAf` instance (`RemoteAf ??=` reuses it). Re-open / sticky Digital can race leftover PortAudio/Pulse state with a new `StartRx`/`StartMic`. Even on a fresh engine, `StartRx` arms the player on the next UDP packet while `StartMic` is still opening capture — concurrent Pulse `Pa_*` → same `n_waiting` abort.
2. **No fail-safe Stop-on-fail.** A thrown `StartMic` (or half-armed RX) leaves streams dirty; the method still starts CAT and **always** `ShowRemoteAfWindow()`.
3. Digital path: `ApplyRemoteAfDevices` (~`:2378-2398`) correctly re-resolves VAC via `FindNamedAfDevice` + `LinuxDigitalIni.DigitalSpeaker` / `DigitalMic` when `RemoteDigitalAudio` is true — keep that; just wrap open with Stop-then-start + guard.

`RemoteAfEngine.StartRx` (`RemoteAudio/RemoteAfEngine.cs` ~`:73-77`) only clears `_playerArmed` and starts UDP — it does **not** stop a live player. `Stop()` (~`:81-87`) stops RX + player + mic. Use that. Do **not** call `StopRemoteAf` from inside `StartRemoteAf` (would also tear CAT / close window).

Note: `RemoteDigitalAudio` is **in-memory** (Remote AF Path Phones/Digital); it is **not** the same INI key as local `DIGITAL_AUDIO` / `IsDigitalAudio`. It survives Remote OFF→ON in the same process. Cold start with only `DIGITAL_AUDIO=1` defaults Remote path to Phones — both must still be smoke-tested.

## 2. Fix (KISS) — match cmd-051 pattern on StartRemoteAf

### 2.1 Rewrite the open body of `StartRemoteAf`

Keep the preamble (allowed check, `RemotePhonesLauncher.StopAll`, `RemoteAf ??=`, log hook, volume/mute). Then:

1. Log before stop, e.g. `Remote AF stop-before-open ({reason})`.
2. `try { RemoteAf.Stop(); } catch { /* ignore */ }` — full Stop (RX + player + mic). Do **not** null `RemoteAf`, do **not** close the window, do **not** touch CAT here.
3. `ApplyRemoteAfDevices();` then set `RemoteAf.MicVolume = RemoteMicVolumeLinear();` again (Digital VAC resolve stays inside `ApplyRemoteAfDevices`).
4. Start with the same guarded pattern as cmd-051:

```csharp
bool rxOk = false, micOk = false;
string host = string.IsNullOrWhiteSpace(Host) ? "127.0.0.1" : Host.Trim();
try
{
    RemoteAf.StartRx();
    rxOk = true;
}
catch (Exception ex)
{
    AppendLog("RX start: " + ex.Message);
}
try
{
    RemoteAf.StartMic(host);
    micOk = true;
}
catch (Exception ex)
{
    AppendLog("Mic start: " + ex.Message);
}
if (!rxOk || !micOk)
{
    try { RemoteAf.Stop(); } catch { /* ignore */ }
    AppendLog($"Remote AF start aborted ({reason}) rxOk={rxOk} micOk={micOk} — stopped clean");
    // Still show the window so Stew can flip Path / retry; do NOT StartRemoteCat on abort.
    ShowRemoteAfWindow();
    return;
}
string seat = RemoteDigitalAudio ? "Digital VAC" : "Phones";
AppendLog($"Remote AF started ({reason}) {seat} TX host={host}:9101 micVol={RemoteAf.MicVolume:0.00}");
```

5. **Only after success:** existing CAT block (`if (RemoteDigitalAudio) StartRemoteCat(); else { StopRemoteCat(); AppendLog(...); }`), then `ShowRemoteAfWindow()`.

Prefer this Stop-then-clean-start over "start Phones first then apply Digital". Do **not** change `ApplyRemoteAfDevicesAndRestart` (already fixed in cmd-051).
