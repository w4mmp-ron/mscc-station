## Why

Avalonia always forces **800** on Connect (`SetPanResolutionAsync(800)`) and has **no** resolution control in `SpectrumWaterfallWindow`. High-res spectrum (and cmd-053 spur-notch checks at 1600/3200) cannot be exercised from the Linux client.

## The change (Avalonia 0.6.69 → 0.6.70)

Roots: `AVA = mscc-ui/Avalonia-Migration/src/MSCC.Avalonia/`

### 1. Sticky setting

In `Services/ClientSettingsStore.cs` / `ClientSettings`:

- Add `public int PanResolutionIndex { get; set; } = 0;` next to Global S/W (`SpectrumZoom`).
- Save under `# Global S/W`: `PAN_RESOLUTION=<0|1|2>` (same key name as WPF).
- Load: clamp `0..2`. Missing key → `0` (Normal 800).
- Helper (local or on settings): bins = index `1→1600`, `2→3200`, else `800`.

Optional: mirror index on `SpectrumDisplaySettings` if that keeps S/W VM cleaner — not required if VM talks to `ClientSettings` + `MainViewModel`.

### 2. S/W UI

In `Views/SpectrumWaterfallWindow.axaml`, in the Spectrum block (near ZOOM / VIEW GRID — same row family as WPF’s REFRESH+resolution area):

- Visible label: **`SPECTRUM RESOLUTION`** (Ron/cmd-054 naming; Avalonia is greenfield so use the new label).
- Tooltip: bins across 72 kHz; higher = sharper / more UDP traffic; use Normal if remote spectrum stutters.
- `ListBox` (or bound ItemsSource) with three items: **Normal (800)**, **High (1600)**, **Max (3200)** — tags/indices 0/1/2.
- Bind to `SpectrumWaterfallViewModel` selected index / selected label.

In `ViewModels/SpectrumWaterfallViewModel.cs`:

- Property for selected resolution index (or item).
- On change (skip while `_loading`): persist `PAN_RESOLUTION`, then ask MainViewModel to apply (see §3). Do **not** call Core from the S/W VM directly if MainWindow/VM ownership is cleaner — either is OK if apply + waterfall clear happen.

### 3. Apply path (MainViewModel)

Replace the hardcode at Connect (~1308):

```csharp
// WAS: await _radio.SetPanResolutionAsync(800);
ApplyPanResolution("connect");  // or await ApplyPanResolutionAsync("connect");
```

Add something like WPF’s `ApplyPanResolution(string reason)`:

1. Resolve bins from sticky `PanResolutionIndex` (800/1600/3200 only).
2. If `_radio` is null / not connected: still persist UI/INI; skip UDP (or only `SetPanResolutionLocal` is inside Core’s async when not started — Core no-ops send when `!_started`).
3. `await _radio.SetPanResolutionAsync(bins)` when connected (Core sends `0x5F` index then refresh blocks=3 — keep that).
4. Clear waterfall on **all** `SpectrumDisplayControl` instances in the main window visual tree (`ClearWaterfall()`), so history lengths match new bin count.
5. Log: `Pan resolution ({reason}): {label} → {bins} bins` (keep the heal intent — applying sticky resolution still sends `0x5F` and refresh).

Wire S/W selection → same method with reason `"S/W"`.
