# Build brief - cmd-055: Windows factory_seed — drop mirror; live wins (Ron answer 4)

**For:** Stew (N8VET)
**Host:** windows-new-hp (Windows `ms-sdr-MKII` only)
**Commit when done. Do not push** (Stew pushes).
**Out of scope:** `rpi/`, `linux/`, WPF / Avalonia UI, firmware.
**No protocol change.**

**Depends on / rides with:** cmd-048 Windows power-cal port (trans owns `power_cal.ini`).
If cmd-048 Windows is not finished yet, do this factory_seed change in the same commit
as the Windows half of cmd-048, or immediately after it. Do not leave the old
`cal\<line>\` → live overwrite in place once ms-sdr no longer mirrors on save.

**Ron (QUESTIONS-FOR-RON.md item 4):** choose **(c) drop the mirror**, **and** change
`load_iq_or_power` so live wins when not switching lines. Same rule for
`power_cal.ini` and `iq.ini`. QRP Reset `0xAA`: WPF never sends it — leave ignored
like the Pi.

---

## Why

Today, at every ms-sdr start, `load_iq_or_power` prefers `cal\<line>\` over live:
if the cal stash exists it copies **cal → live**. After cmd-048, trans writes live
`power_cal.ini` and ms-sdr's `Factory_mirror_live_to_cal("power_cal.ini")` on save
no longer runs, so the cal stash goes stale and a restart would undo the user's QRP
cal. Same trap for `iq.ini` if the write-through mirror is dropped.

## The change

### 1. `mscc-ui/windows-work-tree/ms-sdr-MKII/source/factory_seed.c` — `load_iq_or_power`

Replace the current order (cal → live first, then bootstrap live → cal, then factory)
with Ron's rule. Pass **`switching`** (true when LAST_LINE ≠ current line), not the old
`bootstrap_live = !switching` sense.

```c
/* Call site in Factory_seed_live_inis: */
load_iq_or_power(live, line, "iq", "iq.ini", factory_root, switching);
load_iq_or_power(live, line, "power", "power_cal.ini", factory_root, switching);
```

Logic inside `load_iq_or_power` (leaf is `iq.ini` or `power_cal.ini`):

1. **Not switching and live exists:** copy **live → `cal\<line>\`**, return (**live wins**).
2. **Else** (switching lines, **or** live missing): if `cal\<line>\<leaf>` exists,
   copy **cal → live**, return.
3. **Else** if factory file exists: copy factory → live and factory → cal, return.
4. Else log seed FAILED.

Keep `stash_active_to_cal` on line switch (prev line) as today. Keep
`seed_freq_if_missing` unchanged (freq has no cal\ cache).

### 2. Drop write-through mirror on save

- Remove `Factory_mirror_live_to_cal("power_cal.ini")` from
  `power_calibration.c` `Update_power_ini_file` (or the whole write path goes away
  under cmd-048 — either way, no mirror on power save).
- Remove `Factory_mirror_live_to_cal("iq.ini")` from `iq.c` after TX IQ commit.
- You may keep `Factory_mirror_live_to_cal` itself if `Factory_reseed_live_file` still
  uses it after a factory overwrite into live; that path is fine. Do **not** add new
  save-time mirrors.

### 3. QRP Reset `0xAA`

Leave as on the Pi: ignored / no special Windows reseed for power. WPF never sends it.

## Test

1. QRP-calibrate a band, Accept, stop servers, restart: live `power_cal.ini` value kept
   (not replaced by a stale `cal\<line>\` copy).
2. Same for a TX IQ save + restart (`iq.ini`).
3. Switch radio line (different FW major / product line): previous line stashed; new
   line loads `cal\<newline>\` if present, else factory — not the previous line's live.
4. Delete live `power_cal.ini` only, restart: cal stash or factory restores live.
