## Decision: option A (Stew 2026-09-25), paired with cmd-042

**The RX passband is applied by the server, not by WPF.** WPF sends `CMD_SET_BW_HICUT` (0xD1) as an **index** (`UdpRadioService.SetFilterHighAsync` -> `HighCutHzToIndex`). `ms-sdr` passes it through unchanged and `SDRcore-recv` maps it to Hz: 0=5500, 1=4000, 2=3000, 3=2700, 4=2400. Today there is no case for 5 or 6.

**cmd-042** adds `case 5: 1400.0f` / `case 6: 1000.0f` to all three `SDRcore-recv` trees. On NEW-HP, build **cmd-041 (WPF) and the cmd-042 Windows part together**. Audio narrowing should pass once the new `mscc-recv.exe` is deployed to `C:\mscc-net9\`. Remote hosts (Ubuntu, Pi) narrow once their cmd-042 kits are installed.

**Index contract:** `5 = 1.4 kHz`, `6 = 1.0 kHz`. Appending keeps indices 0-4 and every saved ini/favorite/last-used value valid.

## Why

A fldigi CW user on DIG-U finds the DIG-U filters too wide. The narrowest Hi today is **2.4 kHz**. Keep it simple: add Hi **1.4 kHz** and **1.0 kHz** for DIG-U only, and he'll operate and report back.

## Implement (WPF)

1. **Label and Hz tables (7 entries)** for the **Hi button only**. For example, add `HighCutButtonOptions` = 5.5KHz, 4.0KHz, 3.0KHz, 2.7KHz, 2.4KHz, **1.4KHz**, **1.0KHz**, and extend `HighCutHzValues` to {5500,4000,3000,2700,2400,**1400**,**1000**}. **Leave `HighCutOptions` at 5 items**, because it feeds the default HIGH listbox and 0xDD. Keep label style `"x.xKHz"`.
2. **Mode-aware helpers:** `HighCutCount(mode) = mode == DigU ? 7 : 5` and `NormalizeHighCut(idx, mode)`. For DIG-U, use `((idx % 7) + 7) % 7`. For other modes, clamp idx > 4 to 4 (2.4k); negatives wrap mod 5 as today.
3. **`CycleHighCut`** (`:4010`): `(HighCutIndex - 1 + n) % n`, where `n = HighCutCount(RadioState.ActiveVfo.Mode)`. Keep decrement semantics. The DIG-U order becomes **1.0 -> 1.4 -> 2.4 -> 2.7 -> 3.0 -> 4.0 -> 5.5 -> 1.0** (1.4 and 1.0 sit in their natural spot after 2.4).
4. **`OnHighCutIndexChanged`** (`:4786`), **`ApplyModeFilterProfile`** label fix-up (`:4366`), and **`RecomputeFilterHzForCurrentCutsAndMode`** (`:4467`, `:4502-4503`): replace `% 5` / raw indexing with `NormalizeHighCut` + the 7-entry tables. AM/FM `:4467` should still only ever see 0..4.
5. **Leaving DIG-U with idx 5/6:** any path that makes the mode non-DIG-U while `HighCutIndex > 4` must coerce it to a valid index. The normal path reloads the new mode's profile. The suppressed path (`LoadLastUsedForBand`, VFO snapshot, band presets) must not leave USB/LSB/AM/CW showing 1.0KHz or sending idx 5/6. Clamping to 4 is fine.
6. **`SpectrumWaterfallSettings.SaveModeFilterProfile`** (`:521`): allow highCut **0..6 for DIG-U**, 0..4 for the other modes. Optionally clamp on load (`:858`) so a hand-edited ini can't escape the range.
7. **`MSCC.Core/Services/UdpRadioService.cs` `HighCutHzToIndex`** (`:686`): add `1400 => 5` and `1000 => 6`. This is additive only, and Avalonia never produces those Hz.
8. **Favorites:** `ApplyFavoriteLabels` should label Hi from the 7-entry list so a DIG-U favorite at idx 6 shows 1.0KHz. Favorites/last-used files store raw indices, so no format change is needed.
9. **Guard the 0xDD default echo** (found in the cmd-042 survey). ms-sdr keeps the last 0xD1 in `Filter_High_index`, persists it as `FILTER_HIGH_INDEX`, and on connect sends it to the GUI as `CMD_SET_BW_HICUT_DEFAULT` (0xDD). WPF `DefaultHighCutIndexReported` (`MainViewModel.cs:5630`) writes it straight into `HighCutDefaultIndex`. That drives the **5-item** default HIGH listbox (`MainWindow.xaml:1082`) and echoes 0xDD back (`OnHighCutDefaultIndexChanged` `:4749`). With 5/6 stored, the listbox can coerce to -1, echo -1, and ms-sdr would store 255.
   - **Fix:** in the report handler, ignore idx > 4 (log it, leave `HighCutDefaultIndex` alone, no echo).
   - In `OnHighCutDefaultIndexChanged`, never send a value < 0 or > 4.
10. **No XAML layout change.** The Hi button (`MainWindow.xaml:418`, Width 55) already fits "1.4KHz". Leave the default listboxes and the CW/Lo buttons alone.

## Smoke

1. DIG-U: press **Hi** repeatedly. The label cycles through all 7 values, including **1.4KHz** and **1.0KHz**. The debug log shows `HighCutIndex set: 5 (1.4KHz)` / `6 (1.0KHz)` and `Send high cut index: 5` / `6`.
2. Waterfall/spectrum passband runs from Lo to +1400 / +1000 Hz on the USB side.
3. **Audio (needs the cmd-042 `mscc-recv.exe` in `C:\mscc-net9\`):** at 1.0k/1.4k, fldigi/Phones audio is audibly narrower (band noise and adjacent stations drop). The recv log shows `CMD_SET_BW_HICUT: New filter . Low: ..., High: 1000.000000` / `1400.000000`.
4. Persistence: pick 1.0KHz in DIG-U, restart the client, and DIG-U still shows 1.0KHz (`MODE_DIGU_HIGHCUT=6`). Band change and return keep it (last-used).
5. Other DIG-U choices (5.5/4.0/3.0/2.7/2.4) behave as before.
6. Switch DIG-U (1.0k) -> USB/LSB/AM/CW. Each shows its own profile, and none can reach 1.4/1.0 via Hi. Go back to DIG-U and it's still 1.0k.
7. Rx/Tx tab default HIGH listbox still has 5 items, unchanged.
8. Restart the whole stack (ms-sdr + client) with 1.0k last used. The default HIGH listbox is **not** blanked, the log shows `HighCutDefaultIndex reported: 6` ignored, no -1 is sent, and DIG-U comes back at 1.0k.
9. Remote mode (after Ubuntu/Pi cmd-042 kits): same UI behavior, and host audio narrows.
