## 3. Changes

### 3.1 Controls (both meters, same pattern)

`AnalogSMeterControl.axaml(.cs)` and `AnalogAlcMeterControl.axaml(.cs)`:
- New StyledProperties `HoldEnabled` (bool, default **true**), `PeakEnabled` (bool, default **false**), `PeakHoldSeconds` (double, 2.0). Register Hold/Peak with `defaultBindingMode: BindingMode.TwoWay`.
- axaml: give the checkboxes `x:Name="HoldCheckBox"` / `x:Name="PeakCheckBox"`, remove `IsEnabled="False"` and `Opacity="0.55"`, set the WPF tooltip texts above. Keep the existing sizes/fonts/spacing (180x120 slot). ALC: fix the `:20` comment.
- Code-behind like WPF: checkbox `IsCheckedChanged` -> property (only if different); property change -> sync checkbox (only if different), Hold off snaps `_displayLevel` to raw, Peak off zeroes `_peakLevel`, redraw. No feedback loops.
- Fields `_displayLevel`, `_peakLevel`, `_peakLastRiseUtc`, `DispatcherTimer _ballisticsTimer` (30 ms). Start it in `AttachedToVisualTree`, stop and null it in `DetachedFromVisualTree`.
- `Value` change -> `ApplyRawSample` (clamp 0..15 / 0..100; WPF `ApplyLevelSample` rules). First sample after attach uses `force: true`.
- `BallisticsTick` with the WPF numbers: S-meter hold fall 0.12, peak fall 0.20, thresholds 0.001, peak visible > 0.05; ALC hold fall 0.80, peak fall 1.3, thresholds 0.01, peak visible > 0.3. Hang = `Math.Clamp(PeakHoldSeconds, 0.5, 5.0)`. Redraw only when something changed.

## Known risks

- Checkbox <-> property loops: compare before setting on both sides (WPF does).
- Timer leaks: stop the `DispatcherTimer` on detach; don't start a second one on re-attach or resize.
- `BuildFace` runs on resize and attach (`QueueBuildFace`): it clears the canvas, so recreate the peak needle there and redraw from the stored levels.
- Hold ON by default changes today's feel (needle tracked instantly in 0.6.66). That is the WPF default; don't change it.
- Compiled bindings: the view's `x:DataType` is `MainViewModel`, so the new VM property names must exist or the build fails.
