## 1. What exists today (Avalonia 0.6.67) — the bug

`AVA/ViewModels/MainViewModel.cs`:
- `OnRemoteDigitalAudioChanged` (~`:2243-2251`): when Remote is on, path Phones↔Digital calls `PushAudioToRadio(...)` then **`ApplyRemoteAfDevicesAndRestart("R-path→D"|"R-path→P")`**, then starts/stops Remote CAT.
- `ApplyRemoteAfDevicesAndRestart` (~`:2401-2410`) today:

```csharp
internal void ApplyRemoteAfDevicesAndRestart(string reason)
{
    if (!RemoteAudio || RemoteAf == null) return;
    ApplyRemoteAfDevices();
    RemoteAf.MicVolume = RemoteMicVolumeLinear();
    try { RemoteAf.StartRx(); } catch (Exception ex) { AppendLog("RX restart: " + ex.Message); }
    string host = string.IsNullOrWhiteSpace(Host) ? "127.0.0.1" : Host.Trim();
    try { RemoteAf.StartMic(host); } catch (Exception ex) { AppendLog("Mic restart: " + ex.Message); }
    AppendLog($"Remote AF devices restarted ({reason})");
}
```

- It does **not** call `RemoteAf.Stop()` first. `RemoteAfEngine.StartRx()` (`AVA/RemoteAudio/RemoteAfEngine.cs` ~`:73-77`) only resets `_playerArmed = false` and restarts the UDP receiver — it does **not** stop the live PortAudio player. The player is re-armed on the next UDP packet via `PacketAccepted` while the old Pulse stream may still be in `Pa_WriteStream` / `pa_threaded_mainloop_wait`. Concurrent reopen of mic (`StartMic` does stop-then-open) races the same Pulse mainloop → abort `Assertion 'm->n_waiting > 0' failed`.
- Same restart path is also used from `RemoteAfWindow.axaml.cs` play/mic device changes (~`:153`, `:166`) — fix covers those too.
- `RemoteAfEngine.Stop()` (~`:81-87`) already stops RX + player + mic. Use that. Do **not** call `StopRemoteAf(...)` here (that also tears down CAT / may close the window).

`LinuxPhonePlayer.Start` / `LinuxMicSender.Start` already `Stop()` themselves, but the engine-level race (RX restart + `_playerArmed` flip without stopping the player first, overlapping mic reopen) is what kills Pulse on Linux. WPF uses a different audio stack — leave it alone.

## 2. Fix (KISS)

### 2.1 `ApplyRemoteAfDevicesAndRestart` — full stop, then resolve, then start

Rewrite so every path/device restart does:

1. Log before stop, e.g. `Remote AF stop-before-restart ({reason})`.
2. `try { RemoteAf.Stop(); } catch { /* ignore */ }` — full Stop (RX + player + mic). Do **not** null `RemoteAf`, do **not** close the window, do **not** touch CAT here.
3. `ApplyRemoteAfDevices();` then set `RemoteAf.MicVolume = RemoteMicVolumeLinear();` (same as today).
4. Start again, guarded so a failed open does not leave half-armed streams:

```csharp
bool rxOk = false, micOk = false;
try
{
    RemoteAf.StartRx();
    rxOk = true;
}
catch (Exception ex)
{
    AppendLog("RX restart: " + ex.Message);
}
string host = string.IsNullOrWhiteSpace(Host) ? "127.0.0.1" : Host.Trim();
try
{
    RemoteAf.StartMic(host);
    micOk = true;
}
catch (Exception ex)
{
    AppendLog("Mic restart: " + ex.Message);
}
if (!rxOk || !micOk)
{
    try { RemoteAf.Stop(); } catch { /* ignore */ }
    AppendLog($"Remote AF restart aborted ({reason}) rxOk={rxOk} micOk={micOk} — stopped clean");
    return;
}
AppendLog($"Remote AF devices restarted ({reason})");
```

Keep the existing callers (`OnRemoteDigitalAudioChanged`, RemoteAfWindow play/mic device handlers) unchanged — they already go through this method.

Optional but fine: after a successful restart, the existing seat/device log lines from `ApplyRemoteAfDevices` already print which VAC/Phones devices were chosen — leave those.

### 2.2 Do not change

- `StartRemoteAf` / `StopRemoteAf` / CAT start-stop on Digital (already correct for Remote ON/OFF).
- `RemoteAfEngine.StartRx` / `StartMic` / `Stop` signatures (Stop already does the right three stops).
- WPF `ApplyRemoteAfDevicesAndRestart` / WASAPI path.
- Any other UI, meters, settings, servers.

## Known risks

- Calling `StopRemoteAf(closeWindow: ...)` by mistake would also stop CAT / close the window on a path flip — use **`RemoteAf.Stop()` only**.
- Join/stop timeouts: `LinuxPhonePlayer.Stop` / `LinuxMicSender.Stop` already Join(400); keep that. Do not add sleeps unless a real race remains after Stop-first.
- Half-armed: if StartRx succeeds and StartMic fails (or the reverse), the guard must `RemoteAf.Stop()` again before returning.
- Do not change WPF "to match" — Stew hit this on Avalonia/Linux Pulse only.
