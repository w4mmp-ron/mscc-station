## Ron's position

- QRP cal file management stays in **sdrcore-trans**. ms-sdr should never have managed
  `power_cal.ini`. trans creates it (factory values if missing), loads it and saves it,
  as on the Pi. ms-sdr only reads it to report values to the client.
- Switching radio models is rare. The automatic per-model swap in ms-sdr is overkill and
  is removed. A small manual switch-radio tool does the job instead.

## 1. ms-sdr-MKII: remove the automatic per-model handling

`source/factory_seed.c`, `main.c`, `power_calibration.c`, `iq.c`:

- `main.c:1212`: no more `Factory_seed_live_inis()` swap at startup. If you still want
  missing files seeded at startup, keep only a **seed-if-missing** step (like today's
  `seed_freq_if_missing`): copy `factory\<kind>\<line>\<leaf>` to live **only when the live
  file does not exist**. Never overwrite an existing live file. Do this for `iq.ini` and
  `freq_cal.ini` only; **not** `power_cal.ini` (trans creates that).
- Remove every `Factory_mirror_live_to_cal(...)` call: `power_calibration.c:205`,
  `iq.c:205`, and inside `Factory_reseed_live_file` (`factory_seed.c:255-256`).
- Remove `stash_active_to_cal`, `load_iq_or_power`, `LAST_LINE.txt` handling and the
  `cal\<line>\` folders logic. ms-sdr no longer reads or writes `cal\`.
- **Keep** `Factory_reseed_live_file` for the user's own reset buttons (IQ Reset
  `iq.c:133`, FREQ CAL RESET `calibrate.c:871`): factory -> live for the attached model,
  no mirror.
- QRP Reset `0xAA` (`power_calibration.c:484`): WPF never sends it. Leave it ignored like
  the Pi (trans owns the file).
- Old `cal\` folders on users' disks: leave them, harmless (the tool below may use them).

## 2. Switch-radio tool (Windows first)

A small script (`.ps1`/`.bat`). If a command-line script is not acceptable for Windows
users, make a small GUI with the same steps (model pick list).

Files it handles: `power_cal.ini` and `iq.ini` (the two the old auto-swap handled), in the
live ini folder. Saved sets in `save\<model>\` next to them.

1. Refuse to run while ms-sdr / sdrcore-trans / sdrcore-recv are running.
2. Current model: read `save\CURRENT.txt`. If missing (first run), ask "Which radio is
   attached now?".
3. Ask for the new model. Models = the lines in `Factory_line_from_major`: proficio-legacy,
   proficio-mkii, geminus-legacy, geminus-mkii, ultimus-legacy, ultimus-mkii.
4. Copy the live files to `save\<current model>\`.
5. Copy `save\<new model>\` to live. If there is no saved set for the new model: use
   `cal\<new model>\` from the old auto-swap if present, else the factory files
   (`factory\iq\<model>\iq.ini`, `factory\power\<model>\power_cal.ini`).
6. Write the new model to `save\CURRENT.txt`. Print what was copied.

## Test

1. QRP-calibrate a band, restart the servers: value kept (no swap at startup).
2. TX IQ save, restart: `iq.ini` kept. `cal\<line>\` not touched.
3. Delete live `iq.ini`, restart: seeded from factory (if you kept seed-if-missing).
   Delete `power_cal.ini`, restart: trans recreates it with factory values.
4. IQ Reset / FREQ CAL RESET buttons still reseed from factory.
5. Tool: first run asks for current model; switch A -> B (no saved B: factory used);
   calibrate B; switch B -> A: A's calibration back; switch A -> B: B's calibration back.
6. Tool refuses while the servers run.
