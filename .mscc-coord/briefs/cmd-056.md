## Why

A second STOP while an abort drain is still pending must **not** call
`Cal_Abort_Drain_Done("nothing owed")`. That would clear `cal_abort_pending` and
ACK drain-done to the client too early. Linux already has the `else if (cal_abort_pending)`
log-only branch. Windows always falls into the final `else` and finishes the drain.

## The change

File: `mscc-ui/windows-work-tree/ms-sdr-MKII/source/calibrate.c`

In `case CMD_SET_CAL_ABORT:` replace the **final** log branch only. Windows today
(~lines 772–779):

```c
            if (stepping)
                fprintf(G_fp_logfile, "[%d] CMD_SET_CAL_ABORT: stepping, finish sent\n", line_number++);
            else if (finishing)
                fprintf(G_fp_logfile, "[%d] CMD_SET_CAL_ABORT: finishing, finish already sent\n", line_number++);
            else {
                fprintf(G_fp_logfile, "[%d] CMD_SET_CAL_ABORT: nothing owed\n", line_number++);
                Cal_Abort_Drain_Done("nothing owed");
            }
```

Become (match Linux):

```c
            if (stepping)
                fprintf(G_fp_logfile, "[%d] CMD_SET_CAL_ABORT: stepping, finish sent\n", line_number++);
            else if (finishing)
                fprintf(G_fp_logfile, "[%d] CMD_SET_CAL_ABORT: finishing, finish already sent\n", line_number++);
            else if (cal_abort_pending)
                fprintf(G_fp_logfile, "[%d] CMD_SET_CAL_ABORT: nothing new owed, drain still pending\n", line_number++);
            else {
                fprintf(G_fp_logfile, "[%d] CMD_SET_CAL_ABORT: nothing owed\n", line_number++);
                Cal_Abort_Drain_Done("nothing owed");
            }
```

Do **not** change: drain helpers, `owed` / `old_match` restore block, finish-send on
`stepping`, drop of late `CMD_SET_CALIBRATION_DATA` / `CMD_SET_CAL_DATA_PROCESSED`,
or any other file. Do **not** edit `rpi/`.
