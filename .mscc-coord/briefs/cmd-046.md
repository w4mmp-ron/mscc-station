# Build brief - cmd-046: TUNE POWER is separate (paste-ready for Grok Build)

> ## ⚠️ RULE FROM RON (W4MMP) - NOT NEGOTIABLE
> **TUNE power is TUNE power, that's it.**
> - TUNE power drives **TUNE only**.
> - **No other mode** (USB, LSB, DIG-U, digital audio, remote digital) may use TUNE power.
> - Changing another mode's power must **never** change TUNE power, and the other way round.
>
> This **reverses** the digital -> TUNE_POWER path in SDRcore-trans (3ec263a) and **cmd-045 item 8** (DIG-U slider on Tune power).

**For:** Stew (N8VET)
**Host:** windows-new-hp (Windows), then ubuntu-stew (the `linux/` tree)
**Commit on each host when done. Do not push** (Stew pushes).
**Out of scope:** `rpi/` (**Ron: the Pi servers are not changing for this**; they already follow the rule), Avalonia, Solidus, firmware.

---

## Why

- The Pi `rpi/SDRcore-trans-linux/sources/driver.c` already uses USB_POWER / LSB_POWER for USB/LSB in **every** audio mode. Ron verified it on air (2026-09-25): full power, and the power follows the SSB slider.
- Windows and Ubuntu SDRcore-trans still switch USB/LSB to **TUNE_POWER** when the audio is Digital or Remote Digital.
- cmd-045 made the WPF main slider follow that. So in DIG-U, the slider changes Tune Power.
- The result is that TUNE and digital SSB share one power setting, which breaks the rule above. It's also wrong on the Pi: the slider moves Tune Power, but the transmitter uses SSB Power.

## 1. SDRcore-trans `driver.c` (Windows and Ubuntu)

Files:
- `mscc-ui/windows-work-tree/SDRcore-trans/sources/driver.c`
- `linux/SDRcore-trans-linux/sources/driver.c`

In `Driver_Get_QRO_Power()` and `Driver_Get_QRP_Power()`, `case 'L'` and `case 'U'`: remove the `G_audio_mode == DIGITAL_AUDIO || G_audio_mode == REMOTE_DIGITAL_AUDIO ? ... TUNE_POWER : ...` ternary. Use this instead:

```c
case 'L':
    configured_drive = get_QRO_power_level(G_band, LSB_POWER);   /* QRP: get_QRP_power_level */
    break;
case 'U':
    configured_drive = get_QRO_power_level(G_band, USB_POWER);   /* QRP: get_QRP_power_level */
    break;
```

- Also delete the `/* WSJT is USB ... must use TUNE drive ... */` comment. The Pi shows that digital runs at full power on the SSB bank; if it's low, raise SSB power.
- `case 'T'` stays on TUNE_POWER. `Driver_Get_ALC_Limit()` already uses USB/LSB_POWER; leave it.
- The Pi file is the reference: `rpi/SDRcore-trans-linux/sources/driver.c` (`Driver_Get_QRO_Power` / `Driver_Get_QRP_Power`).

## 2. WPF client `MainViewModel.cs`

`mscc-ui/windows-work-tree/mscc-mscc/mscc-new/src/MSCC.Wpf/ViewModels/MainViewModel.cs`, in `ResolveOperatePowerBank()` (~:1800): **delete** this block:

```csharp
// DIG-U is USB with digital audio. The transmitter uses the Tune power bank for that path.
if (mode == RadioMode.DigU ||
    (mode is RadioMode.USB or RadioMode.LSB && (IsDigitalAudio || RemoteDigitalAudio)))
    return OperatePowerBank.Tune;
```

- Keep the TUN / TUNE mode -> Tune line above it.
- DIG-U, USB and LSB all fall through to `Ssb`.
- If anything else now depends on `IsDigitalAudio` / `RemoteDigitalAudio` only to raise `MainOperatePower*` changes, it can go too. It's harmless if left in.

## 3. WPF tooltip `MainWindow.xaml` (~:2094 and :2096)

Change `LSB/USB→SSB, DIG-U (or Digital audio)→Tune` to `LSB/USB/DIG-U→SSB (any audio)`.
