## 2. F1 - VFO B frequency and mode are lost when MSCC restarts

**Today:** VFO B only lives in memory (`RadioState.VfoB`). `MSCC_LastUsed_VFOB.ini` is the per-**band** last-used file for VFO B (`SpectrumWaterfallSettings.cs:586-587`, path at :1225-1226, `SaveLastUsedForBand(..., forVfoB)` :1259 / `LoadLastUsedForBand(..., forVfoB)` :1295). It is written only while B is the active VFO (`MainViewModel.SaveLastUsedForCurrentBand` :5620-5645, `forVfoB = UseVfoBLastUsedFile` :5551). Nothing at startup puts a frequency or mode into VFO B. The ctor just derives `_bandForVfoB` from `RadioState.VfoB.FrequencyHz` (which is 0) at MainViewModel.cs:1932-1934. After a restart the VFO B mode line (main window item 33) is blank and B has no frequency.

**Fix (client only):**
1. Keep one "current VFO B" record: `VFOB_FREQ`, `VFOB_MODE` (display name, e.g. `DIG-U`, not the wire number) and `VFOB_BAND`. Put them in the `MSCC_LastUsed_VFOB.ini` file as extra keys (the same way `LAST_HF_FREQ` / `LAST_HF_MODE` sit in the client ini, `SpectrumWaterfallSettings.cs:1087-1089`), or in `MSCC_Client.ini`. Pick one and say which.
2. **Write** it whenever VFO B's frequency or mode changes, e.g. from `SaveLastUsedForCurrentBand` when `forVfoB`, and on `SelectVfo` (:4299) when leaving B. Also write it once on close (`MainWindow_Closing`, MainWindow.xaml.cs:1091) if `VfoB.FrequencyHz > 0`. Respect `SuppressLastUsedSave`, so the FREQ CAL / cal-tab CW swaps never get saved as B's mode.
3. **Read** it at startup (after `SpectrumWaterfallSettings.Load`, before or at the first Start) into `RadioState.VfoB.FrequencyHz` / `.Mode` and `_bandForVfoB`. Do **not** make B active and do **not** send it: VFO A stays active at startup, and `SelectVfo(true)` later sends 0xF2 + freq + mode as it does now (`ApplyActiveVfoToRadioAsync` :4338).
4. Make sure the VFO B frequency and mode display refreshes after the load (raise the property changes the VFO B box binds to).
5. Log ` VFO B restored: f=… mode=… band=…` and ` VFO B saved: …`.

### 3c. Closing MSCC while on the FREQ CAL tab must restore mode, filter and pitch

- If AUTO/CHECK is running, send stop/force-off as needed first, or just restore; say which.

- Also add `if (_freqCalEntryHeld) LeaveFreqCalTab();` at the top of `Dispose()` as a backstop (e.g. `App.OnExit`, App.xaml.cs:114).

## 5. G1 - QRP / Full Power / AMP always show the same state

**Today:** three separate states, all sending CMD_SET_PA_BYPASS (0xF7):
- `QrpMode` (`[ObservableProperty] _qrpMode`, MainViewModel.cs:264-265) → `OnQrpModeChanged` :4751 → `SetQrpModeAsync` (Core UdpRadioService.cs:1071). Turning QRP **off** sends QRO.
- `FullPower` (:258-259) → `OnFullPowerChanged` :4743 → `SetFullPowerAsync` (:1046).
- `AmpOn` (:1159) → `OnAmpOnChanged` :1251 → `SetPaBypassAsync` (:1090), plus the dual Tune Power swap (`ApplyTunePowerForAmpState`) and cal-tab enables.
- Server reports (`PaBypassReported`, :5917-5930) update **only** `AmpOn`.
- Commands: `ToggleQrpCommand` :1866, `ToggleFullPowerCommand` :1873, `ToggleAmp` :3645. Buttons: QRP MainWindow.xaml:1152-1168 (DataTrigger `QrpMode`), Full Power :1169-1185 (`FullPower`), AMP :2045.
- So the buttons can disagree, e.g. both QRP and Full Power unlit at startup, or Full Power lit while AMP shows off.

**Fix: one source of truth = `AmpOn`** (it already has the server echo, the Tune Power swap and the guards).
1. Replace the `_qrpMode` / `_fullPower` observable fields with computed properties: `QrpMode => !AmpOn`, `FullPower => AmpOn`. Setters (if kept) just set `AmpOn`.
2. Delete `OnQrpModeChanged` / `OnFullPowerChanged` (no more separate 0xF7 sends). In `OnAmpOnChanged`, raise `OnPropertyChanged(nameof(QrpMode))` and `nameof(FullPower)`. The `PaBypassReported` path then lights all three buttons, because it sets `AmpOn`.
3. Button behaviour (pick this, it's the least surprising): **QRP** click → `AmpOn = false`; **Full Power** click → `AmpOn = true` (so they work as a pair: clicking the one already lit does nothing); **AMP** stays a toggle. Anything that blocks AMP changes (e.g. TX IQ "QRP only", cal tabs) must block the QRP / Full Power buttons the same way, and it will if they go through `AmpOn`.
4. `SetQrpModeAsync` / `SetFullPowerAsync` stay in Core (Avalonia may use them); they just aren't called from WPF any more.
5. **No renames and no removals**: the "Full Power" name and merging the buttons wait for Ron.
6. Log once per change: ` PA path: AMP/Full Power=on|off (QRP=…)`.

## 9. Smoke checklist for Stew (plain language)

1. **VFO B:** set VFO B to, say, 14.074 DIG-U and VFO A to 7.200 LSB. Close MSCC and open it again. VFO B shows 14.074 and DIG-U, and VFO A is still the active one. Click VFO B: the radio goes to 14.074 DIG-U.
2. **FREQ CAL reminder:** AUTO or CHECK shows the amber "Calibration running…" line, and it goes away when the run ends. MANUAL does **not** show it.
3. **Stop on FREQ CAL:** start a CHECK, then press Stop. The amber line goes away, the buttons are usable, and the status says STOPPED. Press Start with the tab still open: the mode goes back to CW with the 200 Hz filter and 600 pitch. Go to MAIN: your old mode comes back.
4. **Close on FREQ CAL:** in USB (or DIG-U), open FREQ CAL and close MSCC with the X. Reopen MSCC: it comes back in USB (or DIG-U) with your usual filter and pitch, not CW.
5. **Messages:**
   - A failed CHECK says "Error may be more than 50 Hz. Run AUTO (COARSE)."
   - After RESET, clicking CHECK warns "Calibration was reset. Run AUTO first." OK still runs the CHECK; Cancel doesn't.
   - After a good AUTO there's no warning.
   - The small counter is labeled "MANUAL steps:".
6. **QRP / Full Power / AMP:** clicking AMP on lights Full Power and turns QRP off, and clicking QRP turns AMP and Full Power off. They never disagree, including right after Start (the server's report sets all three). Tune Power still keeps separate values for AMP on and off.
7. **Radio-model button gone:** there's no Proficio/Geminus button left of the band bar. HF bands are usable on a Proficio (and on Geminus the LF bands, with HF grayed) once the radio reports its firmware.
8. **Power slider:** in DIG-U the slider label says TUNE POWER, and moving it changes the RX/TX tab's Tune Power. In USB with Phones audio it says SSB POWER. In USB with Digital audio it says TUNE POWER. Hover tooltip matches.
